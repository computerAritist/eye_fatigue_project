# Eye fatigue project

라즈베리파이 5의 실시간 눈 인식·조명 제어 프로그램과, WSL/Linux에서 실행하는
녹화 영상 분석 프로그램입니다. MP4 분석은 GPIO, PWM, LCD, I2C 모듈을 import하지
않으며 가상 카메라나 v4l2loopback을 사용하지 않습니다.

## 녹화 영상 분석 실행

프로젝트 루트에서 현재 Python 3.11 가상환경으로 실행합니다.

```bash
.venv/bin/python analyze_video.py /path/to/recording.mp4 \
  --user-id participant_01 \
  --csv results/participant_01.csv
```

`--csv`는 출력 파일의 기준 이름입니다. 위 명령은 다음 5개 파일을 자동 생성합니다.
`--csv results/participant_01_raw.csv`를 지정해도 같은 이름으로 생성됩니다.

```text
results/participant_01_raw.csv             # 기존 17개 항목·소수점 6자리 정밀도 유지
results/participant_01_summary.csv         # 한글 8개 항목, 읽기 쉬운 자릿수
results/participant_01_blink_rate.png       # 분당 깜빡임 환산 횟수
results/participant_01_blink_duration.png   # 평균 감김 시간
results/participant_01_eye_reduction.png    # 정규화 눈 윤곽 면적 감소율
```

기존 명령 형식은 계속 사용할 수 있지만, 이제 원본은 지정한 이름에 `_raw`를 붙여
저장합니다. 이전에 생성한 `participant_01.csv`는 그대로 보존하며 수정하지 않습니다.

영상에는 눈 주변의 기존 빨간 점 12개만 표시하며, 얼굴 전체 랜드마크는 그리지 않습니다.
영상 위쪽의 별도 정보 패널 왼쪽 상단에 현재 측정 구간을 표시하고, 깜빡임 횟수·평균
눈 감김 시간(ms)·평균 눈 윤곽 면적 감소율(%)을 큰 숫자로 표시합니다. EAR·얼굴 검출
여부·영상 시각은 아래쪽에 작은 보조 정보로 표시합니다. 보정 중이거나 평균 표본이
없으면 `N/A`를 표시합니다. 패널을 영상 바깥에 배치하므로 얼굴을 가리지 않으며,
표시 폭에 따라 글자와 패널 크기를 조절합니다. 작은 영상은 여백을 추가해 최소 600픽셀
폭을 확보하고, 영상 비율·검출 입력·측정값·CSV 저장은 그대로 유지합니다.

- 기본값은 처리 가능한 속도로 모든 프레임을 순차 분석합니다. 측정에는 처리 시간이
  아니라 영상 시간이 사용됩니다. 분석 프레임을 건너뛰지 않습니다.
- 영상 속도에 맞춰 화면을 보려면 `--realtime`을 추가합니다. 처리 성능이 원본 FPS보다
  느리면 재생도 느려지지만 측정값의 시간 기준은 유지됩니다.
- GUI 없이 분석하려면 `--no-display`를 추가합니다. 기본 화면 표시는 WSLg/X11/Qt가
  동작하는 환경이 필요합니다.
- `Q`, `Esc`, 창 닫기 또는 `Ctrl+C`로 중단할 수 있습니다. 완료된 구간은 이미 CSV에
  flush되어 있으며, 정상적인 중단에서는 마지막 부분 구간도 저장합니다.
- 기존 출력 CSV·PNG는 기본적으로 덮어쓰지 않습니다. 의도적으로 교체하려면
  `--overwrite`를 사용합니다. 입력 영상과 동일한 파일은 출력 대상으로 허용하지 않습니다.
- `--display-width 1280`은 표시 크기만 제한합니다. 검출 입력 해상도는 변경하지 않습니다.

```bash
# GUI 없이 분석
.venv/bin/python analyze_video.py /path/to/recording.mp4 \
  --user-id participant_01 --csv results/participant_01.csv --no-display

# 원본 영상 시간에 맞춰 표시
.venv/bin/python analyze_video.py /path/to/recording.mp4 \
  --user-id participant_01 --csv results/participant_01.csv --realtime

# 옵션 확인
.venv/bin/python analyze_video.py --help
```

종료 코드는 정상 EOF·화면 종료 `0`, 실행·디코딩 오류 `1`, 보정 미완료 `2`,
`Ctrl+C` 중단 `130`입니다. 보정이 끝나지 않으면 측정 구간이 없으므로 CSV에는 헤더만
남고 경고가 출력됩니다. EOF에서 읽기를 재시도하며 무한 반복하지 않습니다.

분석이 완료되면 터미널에 구간별 요약 표가 출력되고 PNG 3개가 생성됩니다.
정상적인 중단에서도 저장된 구간으로 보고서를 생성합니다. 보정 미완료 시 두 CSV에는
헤더만 남고 그래프에는 측정 구간이 없다고 표시합니다. CSV는 각 구간마다 저장·flush하고,
그래프는 분석 루프가 끝난 뒤 만듭니다. 강제 종료로 그래프가 생성되지 않았더라도
아래 명령으로 저장된 원본 CSV에서 다시 만들 수 있습니다.

## 요약 CSV·터미널·그래프 확인

VS Code에서 `*_summary.csv`를 열거나 Windows Excel로 열어 확인합니다.
원본과 요약 CSV 모두 `utf-8-sig`(UTF-8 BOM)로 저장하므로 한글 열 이름과 사용자 ID를
Excel에서 읽을 수 있습니다.

요약 CSV의 8개 열은 다음과 같습니다.

| 열 | 표시 방식 |
| --- | --- |
| 측정 구간 | `00:05~01:05`; 초 미만을 생략한 표시용 시각. 정확한 시각은 원본 참조 |
| 측정 시간(초) | 소수점 둘째 자리 |
| 눈 깜빡임 횟수(회) | 실제 측정 횟수, 정수 |
| 분당 깜빡임 환산 횟수(회/분) | 횟수 × 60 / 반올림 전 측정 시간; 소수점 첫째 자리 |
| 평균 눈 감김 시간(ms) | 소수점 첫째 자리 |
| 눈 뜸 크기 감소율(%) | 소수점 둘째 자리 |
| 얼굴 검출 성공률(%) | 소수점 첫째 자리 |
| 측정 상태 | `정상`, `부분 구간`, `유효하지 않음`, `유효하지 않음 (부분 구간)` |

예를 들어 48.7201초 구간의 깜빡임이 21회이면 분당 환산값은 **25.9회/분**이며,
측정 상태는 `부분 구간`으로 표시됩니다. 감김 시간 138.669444ms는 `138.7`, 감소율
0.659934%는 `0.66`으로 보입니다. 원본 CSV는 기존 저장 함수와 정밀도를 유지합니다.

`measurement_valid=False`이면 부분 구간 여부와 관계없이 `유효하지 않음`을 명시합니다.
무효이면서 부분 구간인 경우 두 상태를 함께 표시합니다. 원본에 남아 있는 관측값은
요약에서도 확인할 수 있지만, 상태가 정상으로 바뀌지 않습니다. 표본 없는 평균은
CSV에서 빈 값, 터미널에서 `N/A`로 표시하고 0으로 대신하지 않습니다.

터미널 표는 다음 형태입니다.

```text
측정 구간   | 깜빡임(회/분) | 평균 감김(ms) | 눈 크기 감소율(%) | 상태
00:05~01:05 | 15.0          | 138.7         | 0.66              | 정상
01:05~01:53 | 25.9          | 193.5         | 1.04              | 부분 구간
```

`*_blink_rate.png`, `*_blink_duration.png`, `*_eye_reduction.png`는 VS Code의 이미지
미리보기로 각각 열 수 있습니다. 그래프 가로축은 영상 시작 기준 측정 시간(분)이며,
각 점은 해당 구간의 **중간 시각**에 표시합니다. 세로축은 각 지표의 값입니다.

- 유효한 완전 구간: 청록색 원
- 유효한 부분 구간: 주황색 사각형
- 부분 구간의 시간 범위: 주황색 사선 배경. 무효·부분 구간이 겹쳐도 표시
- 무효 구간: 붉은 배경과 하단 붉은 X. 정상 추세선에서는 제외하고 선을 끊음

붉은 X는 축 하단의 **상태 표시**이며 측정값 0을 뜻하지 않습니다. 무효 구간의 원본값은
원본 CSV에 보존됩니다. 모든 구간이 무효이면 그래프에 유효한 측정값이 없다고 표시합니다.
그래프는 한글 폰트 설치 여부와 무관하게 읽을 수 있도록 영문 축·범례를 사용하며,
화면 창을 열지 않는 Matplotlib Agg 렌더러로 PNG를 생성합니다.

기존 CSV로 영상을 다시 분석하지 않고 요약·그래프만 생성할 수도 있습니다.

```bash
# 새 원본 CSV에서 보고서 생성
.venv/bin/python -B -m utils.reporting results/participant_01_raw.csv

# 이전 버전의 17열 CSV도 사용 가능
.venv/bin/python -B -m utils.reporting results/test_user.csv

# 다른 기준 이름으로 생성하거나 기존 요약·그래프 교체
.venv/bin/python -B -m utils.reporting results/test_user.csv --output results/review.csv
.venv/bin/python -B -m utils.reporting results/test_user.csv --overwrite
```

이 명령은 입력 CSV를 읽기만 하며 요약 CSV·PNG 3개만 생성합니다. 원본 CSV를
다시 저장하거나 덮어쓰지 않습니다. 알고리즘, 집계 방식, 측정 유효성 판정도 변경하지
않고 저장된 결과를 그대로 표시합니다.

## 시간 기준과 측정 구간

`VideoCapture`로 읽은 프레임 위치(`CAP_PROP_POS_MSEC`)를 초 단위로 변환하고,
첫 프레임 시각을 0으로 정규화합니다. 모든 검출기에 같은 시각을 전달합니다.
FPS가 0, 음수 또는 비정상 값이면 추정값을 임의로 넣지 않고 오류로 종료합니다.

`--timestamp-mode` 옵션:

| 모드 | 동작 |
| --- | --- |
| `auto` (기본) | 정상적으로 증가하는 영상 타임스탬프 사용. 누락·역행·중복이면 경고 후 FPS 기반 시간으로 전환 |
| `timestamps` | 영상 타임스탬프만 사용. 누락·역행·중복이면 오류로 종료 |
| `fps` | 프레임 번호 / FPS로 계산. 고정 FPS 영상에만 사용 |

**가변 FPS 영상은 `--timestamp-mode timestamps`를 사용하세요.** `auto`의 FPS 대체는
고정 FPS를 가정하며, 가변 FPS 영상의 잘못된 타임스탬프를 복원하지 못합니다.
`auto`가 중간에 FPS 시간으로 전환하면 마지막 정상 시각에서 연속되게 계산합니다.
프로그램 시작에 FPS·프레임 수 메타데이터를, 종료에 FPS 대체 사용 여부를 출력합니다.

보정은 기존과 같이 EAR > 0.23인 첫 프레임부터 5초 경과 구간에서 유효한 눈 크기
표본의 평균을 구합니다. 얼굴 미검출·눈 감김 시간이 보정 시계에서 일시 정지되는
방식은 아닙니다. 보정 완료 시 미완료 깜빡임 상태를 취소하고 측정을 시작합니다.

측정 구간은 보정 완료 시각부터 `[시작, 시작+60초)`로 나눕니다. 보정이 5초에 끝난
60분 영상은 59개의 완전한 구간과 마지막 55초 부분 구간을 갖습니다. 보정 완료 시각은
입력 프레임과 검출 상태에 따라 5초보다 늦을 수 있습니다.

깜빡임 횟수와 감김 시간 이벤트는 **다시 눈을 뜬 완료 시각이 속한 구간**에 배정합니다.
구간 경계에서 진행 중인 감김 상태를 초기화하지 않으며 중복 집계하지 않습니다.
얼굴 미검출은 미완료 감김을 취소합니다. EOF까지 끝나지 않은 감김은 완료 표본에
포함하지 않습니다.

마지막 프레임의 종료 시각은 마지막 프레임 시각에 관측된 마지막 프레임 간격을 더해
계산합니다. 첫 프레임만 있으면 `1/FPS`를 사용합니다. 가변 FPS의 마지막 프레임 길이는
OpenCV 위치 정보만으로 확정할 수 없어 추정값입니다. 마지막 구간 끝은 이 추정의
영향을 받을 수 있습니다. 프레임 수 메타데이터보다 일찍 읽기가 실패하면 일반 EOF로
처리하지 않고 오류를 알립니다. 프레임 수가 알려지지 않은 영상은 읽기 실패만으로
EOF와 손상을 확실하게 구분할 수 없습니다.

## 기존 알고리즘 보존

| 지표 | 기존 계산·기준 |
| --- | --- |
| 깜빡임 횟수 | 양쪽 6점 EAR 평균. EAR < 0.20 시작, EAR ≥ 0.23 종료, 60~1,000ms, 최소 EAR ≤ 0.18 |
| 평균 감김 시간 | EAR < 0.21 시작, EAR ≥ 0.24 종료, 80~2,000ms인 완료 표본의 산술평균 |
| 눈 뜸 크기 감소율 | 각 눈 윤곽 면적 / 눈 가로 길이²의 양안 평균. 초기 기준값 대비 감소율, 최근 15개 유효 표본 평활화, 0~100% 제한 |

세 번째 값은 **EAR 자체의 감소율이 아닙니다.** 기존 보정 방식, 눈 랜드마크 인덱스,
정수 픽셀 좌표, 면적 공식, 평활화 길이와 임계값을 유지합니다. FaceMesh도 기존처럼
두 번 실행하며 각각의 신뢰도 설정(횟수 0.6, 감소율 0.5)을 유지합니다.

MP4의 감소율 평균에는 새 감소율이 계산된 프레임 중 `BlinkDuration.in_blink`가 False인
프레임만 포함합니다. 얼굴 미검출 또는 EAR ≤ 0.23에서 보관되는 이전 감소율은 새 표본으로
집계하지 않습니다. 감김 시간 표본의 인정 기준과 횟수의 인정 기준이 달라, 두 수가
일치하지 않을 수 있습니다.

기존 `update(frame)`, `update(ear)` 호출은 그대로 사용할 수 있으며 기본 시간은
`time.time()`입니다. MP4는 `timestamp=영상시각`을 추가로 전달합니다. 횟수·감김 시간
검출기는 `aggregate_minutes=False`로 내부 분당 집계를 끄고 외부 구간 집계기를 사용합니다.
실시간 경로의 기본 분당 집계는 유지합니다. 얼굴 미검출 뒤에도 감김 시작 시각이 남던
문제는 `BlinkDuration`에서 취소하도록 수정했습니다.

`main.py`, LED/PWM/GPIO/LCD/I2C 제어 파일은 변경하지 않습니다. 실시간 라즈베리파이
실행은 기존처럼 해당 장치와 의존성이 갖춰진 환경에서 `python main.py`를 사용합니다.

## 원본 CSV의 17개 필드

원본 CSV는 Excel에서 한글 사용자 ID를 읽을 수 있도록 UTF-8 BOM으로 저장합니다.
원본·요약 모두 헤더와 각 구간 행을 쓸 때마다 `flush()`하며 모든 영상 프레임을
메모리에 모으지 않습니다. 그래프를 위해 구간별 측정 결과만 보관합니다.
`flush()`는 프로세스 버퍼를 비우며 전원 손실에 대한 디스크 영구 저장 보장은 아닙니다.

| 열 | 의미 |
| --- | --- |
| `user_id` | 실행 인자로 받은 사용자 ID |
| `window_index` | 보정 후 1부터 시작하는 측정 구간 번호 |
| `start_sec`, `end_sec`, `duration_sec` | 영상 시작 기준 초 단위 구간 시작·끝·길이 |
| `blink_count` | 해당 구간에 완료된 유효 깜빡임 횟수. 부분 구간도 실제 횟수이며 분당 환산하지 않음 |
| `mean_blink_duration_ms` | 현재 구간 유효 감김 시간 평균(ms). 표본이 없으면 빈 값 |
| `duration_sample_count` | 평균 감김 시간에 사용된 유효 완료 표본 수 |
| `mean_eye_opening_reduction_pct` | 현재 구간 정규화 눈 윤곽 면적 감소율 평균(%). 표본이 없으면 빈 값 |
| `eor_sample_count` | 평균 감소율에 사용된 유효 표본 수 |
| `face_detection_success_pct` | 두 FaceMesh가 모두 얼굴을 검출한 프레임 수 / 구간 전체 프레임 수 × 100 |
| `frame_count`, `face_detected_count` | 구간 전체 프레임 수, 두 FaceMesh 모두 검출에 성공한 프레임 수 |
| `calibrated` | 보정 완료 여부. 보정 이후부터 집계하므로 정상 생성된 행은 True |
| `is_partial` | 구간 길이가 60초 미만인지 여부 |
| `measurement_valid` | 보정 완료, 얼굴 검출 1회 이상, 감김 시간·감소율 표본 각각 1개 이상, 오류 종료가 아닌 경우 True |
| `end_reason` | `interval`, `eof`, `user_quit`, `interrupted`, `error` |

`measurement_valid`는 세 지표의 평균을 기술적으로 계산할 수 있는지 나타냅니다.
의학적 신뢰도 판정이나 얼굴 검출률의 최소 기준을 의미하지 않습니다. 깜빡임이 0회인
구간도 횟수는 그대로 0으로 저장되지만, 감김 시간 표본이 없으면 평균은 빈 값이고
`measurement_valid=False`입니다. 부분 구간도 표본 조건을 충족하면 True일 수 있습니다.
얼굴 검출 성공률과 함께 해석해야 합니다.

## 의존성과 테스트

현재 프로젝트 가상환경에는 분석 라이브러리가 설치되어 있습니다. 별도 환경을 만들 때는
`requirements-video.txt`를 사용합니다. 기존 빈 파일 `requiremnets.txt`는 건드리지 않았습니다.

```bash
# pip가 있는 Python 3.11 가상환경
python -m pip install -r requirements-video.txt

# uv로 관리하는 가상환경(pip 모듈이 없어도 사용 가능)
uv pip install --python .venv/bin/python -r requirements-video.txt

# 실제 영상 없이 단위 테스트
.venv/bin/python -B -m unittest discover -s tests -v
```

MediaPipe는 Legacy `mp.solutions.face_mesh`를 제공하는 `0.10.21`을 사용합니다.
다른 OpenCV 배포 패키지를 중복 설치하지 않고 `opencv-contrib-python` 하나를 사용합니다.
위 의존성은 현재 Ubuntu 20.04 x86_64 / Python 3.11 환경 기준이며, 라즈베리파이용
패키지·GPIO·I2C 설정을 교체하는 설치 파일이 아닙니다.

테스트는 영상 시간, 60초 경계, 완료 이벤트 배정, 얼굴 미검출 시 상태 취소, 기존 임계값과
면적 공식, 현재 구간 평균, 보정 제외, CSV flush, EOF·중단·디코딩 오류를 확인합니다.
보고서 테스트는 원본 CSV의 바이트 일치, 한글 요약·BOM·자릿수, 부분 구간 환산,
무효·결측값 처리, 원본 파일 보존, 터미널 표, PNG 생성과 그래프의 무효 구간 제외를
추가로 확인합니다. 그래프 생성 의존성 Matplotlib은 `requirements-video.txt`에 포함합니다.
프레임·FaceMesh·VideoCapture를 대체한 테스트는 실제 사람 영상의 검출 정확도를
검증하지 않습니다. 실제 MP4의 얼굴·눈 검출, WSL GUI 표시, 1시간 실영상 성능,
라즈베리파이 하드웨어 회귀 검증은 해당 영상과 장치에서 추가로 수행해야 합니다.
